## Implemented and tested first

- Separate Return to order navigation and Cancel payment with explicit confirmation, ref-based duplicate-action locks, account/route guards, BFCache refresh recovery and actionable errors. Cancellation is atomic, locks parent/suborders and validates member ownership or ticket plus original guest proof. Paid, processing and uncertain legacy attempts cannot be terminally cancelled. New orders may cancel only before any provider attempt. Retry remains available for pending orders; unresolved attempts need supported provider reconciliation, not a browser-return assumption.
- PayFast initiation now uses the inspected server-only prepare_payfast_order contract, verifies current owner/guest/fulfilment state, serializes against cancellation, records issuance and rejects disabled/maintenance gateways. Server configuration is checked before reserving an attempt. Existing signing/encoding and notify processing are unchanged. The local Edge change is type-checked, not deployed by this task.
- Shared string-based SA mobile validation preserves leading zero, supports formatted paste and tel input, and rejects unsupported characters. New guest orders and changed vendor/booking phones are validated in SQL too. Vendor editing has a separate explicit international mode; unchanged historical contacts are preserved. Legacy Track Order proof is compared verbatim rather than rewritten. Registration, customer profile and vendor application have no current phone input/storage field, so none was invented.
- Customer/vendor GPS capture rejects stale/inaccurate/out-of-range positions; customer capture is permission-driven, high-accuracy by default, retryable, configurable and guarded against older completions. Owner-confirmed Eduvos origin is -29.721180,31.071621. Full radius/fee policy is not inferred from “10 KM”; enforcement remains disabled. Admin can configure all missing values in-app on staging.
- Server delivery quotes use Haversine kilometres from the operational origin, check every vendor's coordinates/radius, bind customer/guest/cart, expire after five minutes and are single-use. Creation rechecks vendor delivery eligibility and computes food prices/fee server-side. Once enabled, free-text-only or quote-less legacy checkout is rejected. No browser-supplied fee/distance is accepted. Without GPS the explicit fallback is retry/contact support, not guessed eligibility. Existing checkout remains compatible while enforcement is off.
- Delivery fee/distance snapshots are returned/mapped separately. Order/payment reconciliation subtracts delivery separately from meal gross; CSV exposes that fee. Existing 17% default/overrides, paid commission history and PayFast fee logs are preserved.
- Admin Payments now has server-enforced/audited gateway and delivery controls, maintenance/public notices and timestamps. Browser flags cannot enable gateways; disabling new initiation does not disable existing verification. Gateway settings refresh on focus/poll. Ozow starts disabled/unready and cannot be made ready by a browser administrator.

## Remaining limits

Legacy orders/provider attempts cannot be safely cancelled without reconciliation evidence. A local/network timeout must prompt order-status review before retry. Duplicate PayFast initiation across tabs is still a provider reconciliation concern; the cancellation lock does not claim prevention of all external duplicate charges. Quote GPS is a client-reported coordinate, not cryptographic location attestation; the typed address is not used for pricing. Anonymous quote/checkout abuse limiting and quote-row lifecycle cleanup need operational review. No actual map pin-selection UI is implemented; GPS refusal uses explicit blocking/support fallback when delivery enforcement is enabled.

Actual hosted customer/vendor/admin credentials, email delivery, storage uploads, two-account Realtime delivery, PWA install/upgrade/offline, mobile GPS accuracy, provider cancellation/reconciliation, merchant approval and real PayFast/Ozow payment/webhooks are not certified by these checks. No staging or production launch-readiness claim is made.
